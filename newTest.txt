SENIOR QA AUTOMATION ENGINEER STUDY GUIDE
=========================================
Technical Interview Preparation for Java + Selenium + Database Testing

=== JAVA FUNDAMENTALS ===

BEGINNER LEVEL
--------------

Q: What are the four pillars of OOP in Java?
A: 1) Encapsulation - Data hiding with private fields and public methods
   2) Inheritance - Child classes inherit from parent classes
   3) Polymorphism - Same method behaves differently in different classes
   4) Abstraction - Hiding implementation details through interfaces/abstract classes

Q: What's the difference between ArrayList and LinkedList?
A: ArrayList uses dynamic arrays (fast random access, O(1) get/set)
   LinkedList uses doubly-linked nodes (fast insertion/deletion, O(1) add/remove)
   Use ArrayList for frequent access, LinkedList for frequent modifications

Q: Explain checked vs unchecked exceptions
A: Checked exceptions must be handled at compile time (IOException, SQLException)
   Unchecked exceptions occur at runtime (NullPointerException, ArrayIndexOutOfBoundsException)
   Use try-catch blocks or throws declaration for checked exceptions

Q: What is the difference between == and .equals()?
A: == compares object references (memory addresses)
   .equals() compares object content (must be overridden for custom classes)
   Always use .equals() for String comparison

INTERMEDIATE LEVEL
------------------

Q: Explain Java 8 Stream API with automation example
A: Streams provide functional programming for collections:
   List<String> results = driver.findElements(By.className("result"))
       .stream()
       .map(WebElement::getText)
       .filter(text -> text.contains("PASS"))
       .collect(Collectors.toList());

Q: What are functional interfaces and lambda expressions?
A: Functional interfaces have exactly one abstract method (@FunctionalInterface)
   Lambda expressions provide concise way to implement functional interfaces:
   Predicate<String> isValid = text -> text.length() > 5;
   Function<WebElement, String> getText = WebElement::getText;

Q: How do you handle exceptions in automation frameworks?
A: Use custom exceptions for specific test failures:
   public class ElementNotFoundException extends RuntimeException {
       public ElementNotFoundException(String message) { super(message); }
   }
   Wrap Selenium exceptions with meaningful context

Q: Explain Optional class usage in test automation
A: Optional prevents NullPointerException:
   Optional<WebElement> element = findElementSafely(locator);
   element.ifPresent(WebElement::click);
   String text = element.map(WebElement::getText).orElse("Not found");

ADVANCED LEVEL
--------------

Q: Implement a custom collector for test result analysis
A: public static Collector<TestResult, ?, TestStatistics> toStatistics() {
       return Collector.of(
           TestStatistics::new,
           TestStatistics::accept,
           TestStatistics::combine,
           TestStatistics::finish
       );
   }

Q: How do you implement thread-safe Selenium automation?
A: Use ThreadLocal pattern:
   private static ThreadLocal<WebDriver> driverThreadLocal = new ThreadLocal<>();
   public static void setDriver(WebDriver driver) { driverThreadLocal.set(driver); }
   public static WebDriver getDriver() { return driverThreadLocal.get(); }

Q: Explain reflection usage in test frameworks
A: Reflection allows runtime inspection and modification:
   @Test annotations are processed using reflection
   Page Object initialization can use reflection for field injection
   Custom test listeners use reflection to access test methods

Q: How do you optimize memory usage in large test suites?
A: 1) Use weak references for cached objects
   2) Implement proper cleanup in @AfterMethod
   3) Use parallel streams judiciously
   4) Monitor heap usage with profiling tools

=== SELENIUM AUTOMATION ===

BEGINNER LEVEL
--------------

Q: What are the different types of locators in Selenium?
A: 1) ID - Most reliable, unique identifier
   2) Name - Good for form elements
   3) Class Name - Can match multiple elements
   4) Tag Name - Broad matching
   5) Link Text/Partial Link Text - For links
   6) XPath - Most flexible but slower
   7) CSS Selector - Fast and flexible
   8) Accessibility ID - For mobile testing

Q: What is the Page Object Model?
A: Design pattern that creates object repository for web elements
   Each page is represented as a class with elements and methods
   Improves maintainability and reduces code duplication
   Example: LoginPage class with username, password fields and login method

Q: What are the different types of waits in Selenium?
A: 1) Implicit Wait - Global timeout for element finding
   2) Explicit Wait - Wait for specific condition
   3) Fluent Wait - Explicit wait with polling and exception handling
   Best practice: Use explicit waits for better control

Q: How do you handle dropdowns in Selenium?
A: Use Select class for <select> elements:
   Select dropdown = new Select(driver.findElement(By.id("dropdown")));
   dropdown.selectByVisibleText("Option 1");
   dropdown.selectByValue("value1");
   dropdown.selectByIndex(0);

INTERMEDIATE LEVEL
------------------

Q: How do you handle dynamic elements and AJAX calls?
A: Use explicit waits with expected conditions:
   WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
   wait.until(ExpectedConditions.elementToBeClickable(locator));
   wait.until(ExpectedConditions.textToBePresentInElement(element, "text"));
   For AJAX: wait.until(driver -> ((JavascriptExecutor)driver)
       .executeScript("return jQuery.active == 0"));

Q: Explain the Actions class usage
A: For complex user interactions:
   Actions actions = new Actions(driver);
   actions.moveToElement(element).click().perform();
   actions.dragAndDrop(source, target).perform();
   actions.keyDown(Keys.CONTROL).click(element).keyUp(Keys.CONTROL).perform();

Q: How do you handle multiple windows/tabs?
A: Use window handles:
   String mainWindow = driver.getWindowHandle();
   Set<String> allWindows = driver.getWindowHandles();
   for(String window : allWindows) {
       if(!window.equals(mainWindow)) {
           driver.switchTo().window(window);
       }
   }

Q: How do you implement cross-browser testing?
A: Use WebDriverManager and factory pattern:
   public WebDriver createDriver(String browser) {
       switch(browser.toLowerCase()) {
           case "chrome": return new ChromeDriver();
           case "firefox": return new FirefoxDriver();
           default: throw new IllegalArgumentException("Browser not supported");
       }
   }

ADVANCED LEVEL
--------------

Q: How do you implement parallel test execution with ThreadLocal?
A: public class DriverManager {
       private static ThreadLocal<WebDriver> driver = new ThreadLocal<>();
       public static void setDriver(String browser) {
           driver.set(createDriver(browser));
       }
       public static WebDriver getDriver() { return driver.get(); }
       public static void quitDriver() {
           if(driver.get() != null) {
               driver.get().quit();
               driver.remove();
           }
       }
   }

Q: How do you handle flaky tests?
A: 1) Implement retry mechanism with TestNG IRetryAnalyzer
   2) Add comprehensive logging and screenshots
   3) Use stable locators (data-testid attributes)
   4) Replace Thread.sleep with explicit waits
   5) Implement custom expected conditions

Q: How do you integrate Selenium with CI/CD pipelines?
A: 1) Use headless browser options
   2) Configure Docker containers for browsers
   3) Implement test result reporting (Allure, ExtentReports)
   4) Use environment-specific configuration files
   5) Implement test categorization (@Test(groups = "smoke"))

Q: How do you implement custom ExpectedConditions?
A: public static ExpectedCondition<Boolean> jQueryAjaxCompleted() {
       return driver -> (Boolean) ((JavascriptExecutor) driver)
           .executeScript("return jQuery.active == 0");
   }
   
   public static ExpectedCondition<WebElement> elementToBeRefreshed(WebElement element) {
       return driver -> {
           try {
               element.isEnabled();
               return null;
           } catch (StaleElementReferenceException e) {
               return driver.findElement(By.id(element.getAttribute("id")));
           }
       };
   }

=== DATABASE TESTING ===

BEGINNER LEVEL
--------------

Q: What is JDBC and how do you connect to a database?
A: JDBC (Java Database Connectivity) is API for database operations:
   Connection conn = DriverManager.getConnection(
       "jdbc:mysql://localhost:3306/testdb", "user", "password");
   Statement stmt = conn.createStatement();
   ResultSet rs = stmt.executeQuery("SELECT * FROM users");

Q: What are the basic CRUD operations?
A: CREATE - INSERT INTO table VALUES (...)
   READ - SELECT * FROM table WHERE condition
   UPDATE - UPDATE table SET column=value WHERE condition
   DELETE - DELETE FROM table WHERE condition

Q: How do you validate data after UI actions?
A: 1) Perform UI action (e.g., create user)
   2) Query database to verify data was inserted
   3) Compare expected vs actual values
   4) Clean up test data

Q: What's the difference between Statement and PreparedStatement?
A: Statement - Used for static SQL queries, vulnerable to SQL injection
   PreparedStatement - Precompiled SQL with parameters, prevents SQL injection
   Use PreparedStatement for dynamic queries with user input

INTERMEDIATE LEVEL
------------------

Q: How do you implement database setup and teardown?
A: @BeforeMethod
   public void setupTestData() {
       executeQuery("INSERT INTO users (name, email) VALUES ('Test', 'test@test.com')");
   }
   
   @AfterMethod
   public void cleanupTestData() {
       executeQuery("DELETE FROM users WHERE email = 'test@test.com'");
   }

Q: How do you handle transactions in test automation?
A: Connection conn = getConnection();
   conn.setAutoCommit(false);
   try {
       // Execute test operations
       conn.commit();
   } catch (Exception e) {
       conn.rollback();
       throw e;
   }

Q: How do you validate referential integrity?
A: Test foreign key constraints:
   // Insert parent record
   executeQuery("INSERT INTO customers (id, name) VALUES (1, 'John')");
   // Insert child record
   executeQuery("INSERT INTO orders (id, customer_id) VALUES (1, 1)");
   // Verify relationship
   ResultSet rs = executeQuery("SELECT c.name, o.id FROM customers c JOIN orders o ON c.id = o.customer_id");

Q: How do you perform database performance testing?
A: long startTime = System.currentTimeMillis();
   ResultSet rs = executeQuery("SELECT * FROM large_table WHERE indexed_column = 'value'");
   long executionTime = System.currentTimeMillis() - startTime;
   Assert.assertTrue(executionTime < 1000, "Query took too long: " + executionTime + "ms");

ADVANCED LEVEL
--------------

Q: How do you implement connection pooling in test automation?
A: Use HikariCP or Apache Commons DBCP:
   HikariConfig config = new HikariConfig();
   config.setJdbcUrl("jdbc:mysql://localhost:3306/testdb");
   config.setMaximumPoolSize(10);
   HikariDataSource dataSource = new HikariDataSource(config);

Q: How do you handle database differences across environments?
A: Use configuration files and database abstraction:
   Properties dbProps = loadProperties("database-" + environment + ".properties");
   String query = getQueryForDatabase(dbProps.getProperty("db.type"));

Q: How do you implement database mocking for unit tests?
A: Use H2 in-memory database or Mockito:
   @Mock private Connection mockConnection;
   @Mock private PreparedStatement mockStatement;
   when(mockConnection.prepareStatement(anyString())).thenReturn(mockStatement);

Q: Write a complex SQL query for test validation
A: -- Find customers with orders above average order value in last 30 days
   SELECT c.customer_id, c.name, COUNT(o.order_id) as order_count, 
          AVG(o.total_amount) as avg_order_value
   FROM customers c
   JOIN orders o ON c.customer_id = o.customer_id
   WHERE o.order_date >= DATE_SUB(NOW(), INTERVAL 30 DAY)
   GROUP BY c.customer_id, c.name
   HAVING AVG(o.total_amount) > (
       SELECT AVG(total_amount) FROM orders 
       WHERE order_date >= DATE_SUB(NOW(), INTERVAL 30 DAY)
   )
   ORDER BY avg_order_value DESC;

=== TEST SYSTEM DESIGN ===

BEGINNER LEVEL
--------------

Q: What are the components of a test automation framework?
A: 1) Test Layer - Test classes and methods
   2) Page Object Layer - UI element representations
   3) Utility Layer - Common functions and helpers
   4) Configuration Layer - Environment and test data
   5) Reporting Layer - Test results and logs
   6) CI/CD Integration Layer

Q: What is the difference between smoke, sanity, and regression testing?
A: Smoke Testing - Basic functionality verification after build
   Sanity Testing - Narrow regression testing after minor changes
   Regression Testing - Complete testing to ensure no existing functionality is broken

Q: How do you organize test data?
A: 1) External files (JSON, YAML, Excel)
   2) Database test data
   3) Test data builders/factories
   4) Environment-specific configuration
   5) API-generated test data

Q: What are the benefits of Page Object Model?
A: 1) Code reusability and maintainability
   2) Separation of test logic from UI logic
   3) Easy maintenance when UI changes
   4) Better readability and organization

INTERMEDIATE LEVEL
------------------

Q: How do you implement test categorization and execution?
A: Use TestNG groups:
   @Test(groups = {"smoke", "regression"})
   public void loginTest() { }
   
   TestNG XML configuration:
   <groups>
       <run>
           <include name="smoke"/>
       </run>
   </groups>

Q: How do you implement data-driven testing?
A: @DataProvider
   public Object[][] testData() {
       return new Object[][] {
           {"user1", "pass1"},
           {"user2", "pass2"}
       };
   }
   
   @Test(dataProvider = "testData")
   public void loginTest(String username, String password) { }

Q: How do you handle test dependencies?
A: Use TestNG dependencies carefully:
   @Test
   public void createUser() { }
   
   @Test(dependsOnMethods = "createUser")
   public void updateUser() { }
   
   Better approach: Make tests independent with proper setup/teardown

Q: How do you implement custom test listeners?
A: public class TestListener implements ITestListener {
       @Override
       public void onTestFailure(ITestResult result) {
           takeScreenshot(result.getMethod().getMethodName());
           logError(result.getThrowable());
       }
   }

Q: How do you implement test result analytics and reporting?
A: 1) Integrate with Allure/ExtentReports for rich reporting
   2) Store test results in database for trend analysis
   3) Create dashboards with test metrics
   4) Implement failure categorization and root cause analysis
   5) Set up alerts for test failure thresholds

Q: How do you handle test environment management?
A: 1) Infrastructure as Code (Terraform, CloudFormation)
   2) Environment provisioning automation
   3) Test data management across environments
   4) Service virtualization for dependencies
   5) Environment health monitoring

Q: How do you implement continuous testing in DevOps pipeline?
A: 1) Shift-left testing with unit and integration tests
   2) Parallel test execution in CI/CD pipeline
   3) Automated test environment provisioning
   4) Fast feedback loops with immediate notifications
   5) Test result integration with deployment decisions
   6) Production monitoring and synthetic testing
